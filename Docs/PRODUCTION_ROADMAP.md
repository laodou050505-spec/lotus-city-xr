# 《一念莲城》PICO 空间塔防制作与验收流程

## 阶段 1：空间原型与视角（已完成）

- 使用官方 Unity 6 建立独立项目，不使用 Tuanjie。
- 将 three.js 网格、路径和塔防规则迁移到真实米制的 3D 沙盘桌，尺寸约 2.2 x 1.76 米；主题改为守护寺院、净化心魔，不把佛像作为炮塔或攻击目标。
- 采用下层水岸山门、中层回廊、上层主殿与长明心灯的三层立体路线，敌人通过台阶、桥梁和洞门逐级上行。承载体已重建为三层不规则风化岩岛，战斗面随山势起伏而不是平整桌板。
- 66 个作者保留的玩法格使用用户模型库的真实三维石板：21 个敌人路线格使用乳白 `S-02`，45 个武器部署格使用苔绿色 `S-17`；被删除的格子和远离路线的逻辑格不渲染棋盘砖。
- 主殿、回廊、石窟、主佛龛、山门、桥、树、祈愿幡和石灯笼等真实 FBX 已完成初版地编；非玩法模型通过 `EditableSceneModelLayout` 暴露位置、旋转、大小和显隐，后续可自由调整而不修改玩法数据。
- 沙盘锚定在房间坐标；PICO 玩家可以用 6DoF 绕桌观察。
- 提供鼠标、键盘、滚轮的电脑绕桌测试，不把游戏退化成屏幕平面展示。

验收：桌面版可从四周观察，塔、敌人、遮挡和世界空间状态牌保持正确。

## 阶段 2：PICO 与 Android 基础（已完成）

- 接入官方 PICO Unity SDK `6.0.0` 和 `PXR_Loader`。
- 配置 Android Activity、ARM64、IL2CPP、OpenGL ES 3 和 Multiview。
- 接入左手卡牌/塔操作射线、左扳机、左手 A/X，右手攻击射线、右扳机、右手 B、双握把与双手触觉反馈。
- 使用 PICO SDK 官方左右控制器 Profile 和模型；左手负责卡牌、摆放、搬家与合成，右手负责玩家攻击，重定位与触觉反馈已绑定。
- Android/PICO 启用透明相机、`PXR_Manager.EnableVideoSeeThrough` 与 MR safeguard，目标体验为悬浮在真实房间中的立体寺院沙盘，而不是平面 Unity 画面。
- 提供 PICO 开发 APK 和无头显电脑测试版。

验收：Unity 自动验证 Loader、渲染模式、架构、脚本后端与 Input System。

## 阶段 3：玩法升级（已完成）

- 扩展为 8 波和 6 类心魔：妄念尘、贪相、无明兽、疑障、嗔火、痴雾。
- 防御建筑分为晨钟、经幢、莲灯三类并扩展到三级；等级会增强伤害、射速、范围、弹速及净化效果，模型通过屋顶层数、塔基面积、灯数量、经幢数量和法轮尺寸表现结构逐步完整。
- 合并完全由玩家触发：拖动一座塔模型靠近另一座同类型、同等级塔后自动吸附，松手时一级合成二级，二级合成三级，不要求射线精确命中目标碰撞体；一级卡牌拖到场景中的同类一级塔附近也可直接升级。
- 禁止不同类型、不同等级、自身以及三级塔继续合并；无效拖动回原格。
- 合并提供目标环、音效、触觉和粒子反馈。
- 已部署塔可以继续拖到空格搬家，不重新收费；玩家右手武器可以独立攻击所有波次敌人。
- 敌人根节点严格沿玩法路径推进，模型子节点增加起伏、步态、侧摆、悬浮与转弯平滑；自然动画不改变寻路、受击或到达核心的判定位置。

验收：规则烟雾测试会把拖动模型放入目标吸附半径，确认自动识别、生成三级塔、拒绝非法组合并保持塔可搬家；桌面测试版可运行。

## 阶段 4：美术、音频与特效（本轮完成）

- 三类防御塔的一级至三级模型、六类敌人模型和寺院地编模块均已替换为用户提供的真实模型，不再显示早期粗制占位小模型。
- 2026-08-05 完成寺院地编升级：连续风化岩基座分为底层、中层、上层，形成带不规则岩沿和高度变化的三阶山丘；下层水岸山门、中层回廊、上层主殿佛龛的空间主次已经建立。两个外观不符合要求、带巨大木栏的 `S-01` 导入件默认隐藏。
- 柔化主光强度，并以冷色补光、暖色灯火控制层次；材质方向为乳白石材、低饱和青绿、深木色和少量暖金，避免过曝与单一色调。
- 已接入攻击拖尾、三类净化圆环、右手法器命中特效，以及空间 UI 的合并/目标反馈。
- 已接入许可清晰的循环 BGM、塔放置音效和胜利音效；其余素材缺失时保留程序化空间音效回退。
- 外部素材必须优先从 `ange-embed` 检索，确认作者、来源 URL 和许可证后才可导入。
- 2026-08-04 已按 v2 流程检查场景道具、音乐、攻击音效和 UI 音效分类；候选记录仍缺少可核验的作者、原始来源和可再分发许可证字段，因此不导入来源不明资源。

验收：见 `Docs/ASSET_ATTRIBUTION.md`；任何新增文件必须补齐来源和许可证。

## 阶段 6：真机验收（有头显后）

1. 验证头部和双手柄 6DoF、射线、扳机、按键和触觉。
2. 从桌子四个方向测试拖动合并，检查射线遮挡和松手容错。
3. 测试站姿、坐姿、边界重置、失焦、控制器断连与应用恢复。
4. 根据实际房间调整桌高、桌距、射线长度和左右利手设置。
5. 真机 Profile CPU、GPU、内存、温度和最拥挤波次帧率。

首要性能风险：棋盘的 66 个三维砖模型（21 个 `S-02`、45 个 `S-17`）仍需真机 Profile。根据 GPU 时间和最拥挤波次帧率决定低模替换、静态合批或网格合并；在完成这一步前，不将电脑流畅度视为 PICO 性能结论。

发布门槛：完整 8 波稳定运行；连续 30 分钟无增长型内存问题；控制器断连可恢复；无必须依赖平面 UI 的核心操作。
